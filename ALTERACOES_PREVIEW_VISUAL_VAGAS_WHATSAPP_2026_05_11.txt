ALTERAÇÕES — Preview visual específico por vaga no WhatsApp

Arquivos alterados/adicionados:
- script.js
- vercel.json
- api/vaga-preview.js
- SQL_OPCIONAL_VAGAS_PREVIEW_OG.sql

O que mudou:
1) O botão "Compartilhar vaga" agora compartilha link bonito no formato:
   https://www.rhimob.com.br/vaga/slug-da-vaga

2) Foi criada a rota dinâmica no Vercel:
   /vaga/:slug -> /api/vaga-preview?slug=:slug

3) A função /api/vaga-preview.js busca a vaga ativa no Supabase, monta HTML server-side com:
   - og:title
   - og:description
   - og:image
   - og:url
   - twitter:card

4) Depois de gerar o preview, a página redireciona o usuário para:
   /vagas.html?vaga=ID_DA_VAGA#vagas

5) O WhatsApp passa a enxergar os metadados da vaga antes do JavaScript do site carregar.
   Isso resolve o problema de todas as vagas aparecerem com o mesmo preview genérico.

Variáveis recomendadas no Vercel:
- RHIMOB_SUPABASE_URL
- RHIMOB_SUPABASE_ANON_KEY
- RHIMOB_SITE_VAGAS_TABLE, opcional, padrão site_vagas_publicas
- RHIMOB_DEFAULT_OG_IMAGE, opcional

Observação:
- O arquivo api/vaga-preview.js tem fallback para a chave pública já usada no front-end, mas o ideal é configurar as variáveis no Vercel.
- Nunca colocar service_role no HTML, JS público ou repositório.

Opcional no Supabase:
- Rodar SQL_OPCIONAL_VAGAS_PREVIEW_OG.sql para adicionar slug e imagem_og na tabela de vagas.
